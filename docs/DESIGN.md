

# adze 设计文档：

用 Go 实现轻量级本地 code agent。

这份文档参考 Codex 和 Claude Code 的设计，分 8 个阶段，**从简单到复杂**地实现一个本地运行的 code agent。每个阶段包含三块：**目标**、**要学的 Go 知识**、**核心代码骨架和讲解**。代码只给骨架和关键部分，具体实现自己完成。

---

## 一、整体认识：code agent 的本质

Codex 和 Claude Code 结构很复杂，但核心都是一个循环：

```
用户输入 → [发给模型(带工具列表)] → 模型回复
              ↑                         │
              │        有 tool_calls? ──┤── 没有 → 输出答案，结束
              │                         │ 有
              └── 把工具结果追加到历史 ←── 执行工具(读文件/改文件/跑命令)
```

其他功能都是在这个循环外面加的：权限审批、沙箱、上下文压缩、流式输出、会话持久化、子 agent、MCP。所以先把循环跑通，再一层层往上加。

```
adze/
├── go.mod                  # 模块定义（类似 package.json / requirements.txt）
├── cmd/adze/main.go        # 程序入口
└── internal/               # internal 下的包只能被本模块引用（Go 编译器强制）
    ├── llm/                # 和模型通信
    ├── tools/              # 工具实现
    ├── agent/              # agent 循环
    ├── permission/         # 审批
    └── config/             # 配置
```


依赖方向是单向的：`agent` 依赖 `llm` / `tools` / `permission`，而 `llm` 不知道 agent 的存在。`internal/` 目录下的包只能被本项目引用，Go 编译器会强制这一点。

> **Go 知识：module 与 package**
> - **module**：一个项目，由 `go.mod` 定义。`go mod init github.com/你/adze` 会生成它。
> - **package**：一个目录就是一个包，目录里所有 `.go` 文件第一行都写 `package xxx`。
> - `package main` 加 `func main()` 才能编译成可执行文件。
> - 首字母**大写**的名字（`Chat`、`Message`）是导出的（public），**小写**是包内私有的。Go 没有 `public` 和 `private` 关键字，全靠大小写区分。

## 二、分阶段实现

### 阶段 0：项目骨架

**目标**：能编译、能运行。

**做什么**：
- 用 `go mod init` 建立模块。
- 建立 `cmd/adze/main.go`，打印一行文字。
- 熟悉 `go run`、`go build`、`go vet`、`go fmt` 四个命令。

**学到的 Go 概念**：module、package、`package main` 与 `func main`、导出与未导出（首字母大小写）。

**验收**：`go run ./cmd/adze` 有输出。

---

### 阶段 1：单轮对话

**目标**：`adze "用 Go 写个快排"` 能把问题发给本地模型并打印回答。

**做什么**：
- 定义消息结构（角色 + 内容）和请求 / 响应结构，字段与 OpenAI 接口对齐。
- 写一个最小的 HTTP 客户端：POST 到 `/chat/completions`，解析 JSON 响应。
- 把命令行参数拼成一条 user 消息发出去，打印模型回答。
- 用 `httptest` 起一个假服务器写单元测试，不需要真的模型也能测。

**关键设计点**：
- 只依赖 OpenAI 兼容协议，不绑定某一家。默认指向 Ollama，换 LM Studio / vLLM / 云端只改地址和模型名。
- HTTP 客户端的超时交给 `context` 控制，不设死时长，因为 agent 一次运行可能要好几分钟。
- 错误要带上下文，方便定位（是网络问题、HTTP 状态问题，还是 JSON 解析问题）。

**学到的 Go 概念**：struct、struct tag、JSON 编解码、`net/http`、`error` 返回值与 `%w` 包装、`defer`、指针、`context`。

**验收**：`go test ./...` 通过；真实模型下一次问答正常。

---

### 阶段 2：多轮对话（REPL）

**目标**：进入交互模式，能连续提问，模型记得上下文。

**做什么**：
- 读标准输入，循环读取一行输入并发给模型。
- 把每次的用户消息和助手回复追加到历史，下次请求整体带上。
- 增加 `/exit`、`/clear` 这类命令；`/clear` 只保留系统提示。

**关键设计点**：
- 历史是个切片，只增不减（裁剪放到阶段 8）。
- 用户的输入方式要统一：后续做权限确认时，也要从同一个输入源读，不能两处各自缓冲标准输入。

**学到的 Go 概念**：`for` 循环（Go 只有 for）、`switch`、切片与 `append`、`bufio.Scanner`。

**验收**：先说「我叫小明」，再问「我叫什么」，模型答对。

---

### 阶段 3：工具系统（只读工具）

**目标**：模型可以主动读文件、看目录，而不是凭空猜测。

**做什么**：
- 定义统一的工具接口：名称、描述、参数结构、是否只读、执行方法。
- 用注册表管理工具：按名字查找、生成给模型看的工具列表。
- 实现两个只读工具：读取文件（带行号，支持分页）和列目录。
- 在 prompt 里教会模型工具协议：它返回的「工具调用」包含名字和参数字符串，我们执行后要把结果和调用 ID 对应着追加回历史。

**关键设计点**：
- 工具执行出错时不要把程序搞崩，而是把错误文本当作工具结果交回给模型，让它自己修正参数。
- 所有路径都必须限制在工作目录内，防止 `../` 越界。
- 工具描述要短、要具体，小模型才不容易选错工具。

**学到的 Go 概念**：`interface` 与隐式实现、`map`、`any`、`json.RawMessage`（先不解析、交给工具自己解析）、可变参数、`path/filepath`。

**验收**：问「这个项目的 main 函数在哪、做了什么」，模型先列目录、再读文件，然后回答。

---

### 阶段 4：agent 循环（核心）

**目标**：模型能连续调用多个工具，直到完成任务。

**做什么**：
- 实现循环：发请求 → 追加助手消息 → 有工具调用就逐个执行并追加结果 → 再发请求。
- 设置最大轮数，防止模型原地打转。
- 每次工具调用打印一行提示，让用户看得见 agent 在做什么。
- 写系统提示：工作目录、操作系统、先调查再动手、任务完成后简短总结。

**关键设计点**：
- 助手消息（含工具调用）和对应的工具结果必须成对出现在历史里，顺序不能乱，否则接口会报错。
- 工具调用的 ID 要一一对应；模型没给 ID 时我们自己补一个。
- 一轮里有多个工具调用时，全部执行完再发下一次请求。

**学到的 Go 概念**：把前几个阶段的东西组合起来；`errors.New`、格式化输出。

**验收**：能完成「看看项目结构，然后解释入口」这类需要多次工具调用的任务。

---

### 阶段 5：写类工具（能真正改代码）

**目标**：能新建文件、修改文件、运行命令。

**做什么**：
- `write_file`：新建或整体覆盖文件，自动建目录。
- `edit_file`：精确字符串替换，要求待替换文本在文件中唯一；找不到或不唯一时给出可操作的错误提示。
- `bash`：在工作目录下执行命令，带超时，合并输出并截断过长结果。
- `grep`：按正则搜索文件内容，支持文件名过滤和结果条数上限，跳过二进制文件与依赖目录。
- `glob`：按通配符（支持 `**`）找文件。

**关键设计点**：
- 小模型写整份长文件容易漏行，写 diff 容易算错行号。「唯一字符串替换」是最稳的编辑方式。
- 命令超时要能杀掉进程；输出太长必须截断，否则一次 `cat` 就把上下文撑爆。
- 搜索类工具要有条数上限，并告诉模型结果被截断了。

**学到的 Go 概念**：`os/exec` 与 `CommandContext`、`context.WithTimeout`、`regexp`、`filepath.WalkDir`、闭包、`fs.DirEntry`。

**验收**：让它「新建 hello.go，加一个加法函数和测试，然后跑 go test」，能完整走通。

---

### 阶段 6：权限与安全

**目标**：危险操作先问人。

**做什么**：
- 三种模式：`ask`（读写命令都问）、`auto-edit`（写文件自动放行，命令仍问）、`full-auto`（全部放行）。
- 只读工具永远放行。
- 用户可以选择「总是允许某个工具」，本次会话内不再询问。
- 拒绝时把「用户拒绝」作为工具结果告诉模型，让它换思路，而不是反复重试。

**关键设计点**：
- 审批放在 agent 执行工具之前，作为唯一入口，不在每个工具里各写一遍。
- 再叠加一层硬规则：危险命令黑名单、写路径必须落在工作目录内。
- 命令行参数里的权限模式要能被 `/mode` 命令临时切换。

**学到的 Go 概念**：`const` 与 `iota`、实现 `String()` 让枚举好打印、回调函数（把「怎么问用户」交给 main 提供）。

**验收**：`ask` 模式下改文件会询问；选「总是允许」后同类操作不再问。

---

### 阶段 7：流式输出与中断

**目标**：边生成边显示；按 Ctrl-C 只中断当前任务，不退出程序。

**做什么**：
- 把请求改成流式，逐行解析 SSE（`data: {...}` 与 `data: [DONE]`）。
- 文本增量直接打印；工具调用是分片到达的，要按序号把参数拼完整。
- 每轮对话创建一个可取消的 context，Ctrl-C 取消它；被取消后历史里不能留下半条工具调用。

**关键设计点**：
- 流式下工具调用参数是一段段字符串，必须按 index 累积，这是最容易出 bug 的地方。
- 中断后要修补历史：如果有工具调用没有结果，补一条「已中断」的结果，保证下一轮请求合法。

**学到的 Go 概念**：goroutine、channel、`select`、`os/signal` 与 `signal.NotifyContext`。

**验收**：回答逐字出现；生成中点 Ctrl-C 立即停止，且能继续下一轮。

---



### 阶段 8：上下文管理，小模型的生死线

小模型上下文短、注意力弱，这一层决定了 agent 好不好用。

**目标**：长时间使用不爆上下文。

**做什么**：
1. **截断工具输出**：保留头部 N 行和尾部 N 行，中间写 `...[省略 X 行]...`（Codex 就是这么做的）。
2. **读文件分页**：`read_file` 支持 `offset` 和 `limit`，默认最多 500 行（Claude Code 的 Read 就是这样）。
3. **token 估算**：粗略按 `len(text)/4` 算（中文可以按 `utf8.RuneCountInString` 乘一个系数）。超过窗口 70% 时触发压缩。
4. **压缩（compact）**：把最早的若干轮发给模型做摘要，用一条 `{"role":"user","content":"[之前的对话摘要] ..."}` 替换它们，只保留 system 和最近几轮。⚠️ 切分时不能把 assistant 的 tool_calls 和对应的 tool 结果拆开，否则接口会报错。
5. **AGENTS.md**：启动时从当前目录往上找，找到就拼进 system prompt。
6. **小模型专属技巧**：
   - 工具数量控制在 6 个以内，description 一两句话说清楚。
   - temperature 设 0.1~0.3。
   - **降级方案**：有些模型不支持原生 tool calling。可以在 prompt 里约定模型输出 ```` ```tool {"name":..,"arguments":{..}} ``` ````，自己用正则解析。抽象一个 `ToolCallParser` 接口，两种模式就能切换（又是一个 interface 的实战）。
   - JSON 解析失败时把错误返回给模型重试，不要直接失败。


**关键设计点**：
- 小模型的上下文窗口小、注意力弱，工具数量和输出长度都必须克制。
- 温度调低，减少胡编。
- 如果模型不支持原生工具调用，可以退化成「让模型输出特定格式的 JSON」，再自己解析。

**学到的 Go 概念**：`rune` 与 UTF-8（按字符截断，别切坏中文）、按字符数估算、结构化的历史裁剪。

> **Go 知识**：`unicode/utf8`。Go 的 string 是 UTF-8 **字节**序列，`len("你好")` 等于 6。按字符遍历要用 `for _, r := range s`，这里 r 是 `rune`（Unicode 码点）。截断中文时一定要注意别把一个字切成两半。


**验收**：连续问十几个问题不报上下文超限；大文件读取不会一次灌满上下文。

## 三、学习路线对照表

| 阶段 | 新学的 Go 概念 |
|---|---|
| 0 | module、package、main、go 工具链 |
| 1 | struct、tag、JSON、http、**error**、defer、指针、context |
| 2 | for、switch、**slice/append**、bufio |
| 3 | **interface**、map、comma-ok、可变参数、filepath |
| 4 | 组合以上，写出第一个完整程序 |
| 5 | os/exec、超时、闭包、regexp、WalkDir |
| 6 | const/iota、Stringer 接口 |
| 7 | **goroutine、channel、select**、signal |
| 8 | rune/UTF-8、抽象设计 |
| 9+ | testing、sync、泛型、第三方库 |

**参考资料**：
- [A Tour of Go](https://go.dev/tour)：阶段 0 之前过一遍
- [Go by Example](https://gobyexample.com)：遇到具体 API 时查
- [Effective Go](https://go.dev/doc/effective_go)：阶段 4 之后读，理解 Go 的风格
- 对照阅读开源实现：Codex 是开源的（Rust），有些社区 Go agent 项目（比如 opencode 的早期版本）也值得看看

### 建议节奏

- **先做到阶段 4**，大概一个周末，就有一个能读代码、能回答问题的 agent，成就感最强。
- **阶段 5、6** 让它能真正改代码。
- **阶段 7、8** 让它好用。
- 每个阶段结束都 commit 一次，方便回顾学习轨迹。
